# Заместитель (Proxy)

## Какую проблему решает

В кофейне стоит большая кофемашина. С ней связано несколько неудобств:

- включать её долго (прогрев бойлера), и незачем делать это, пока никто не заказал кофе;
- пользоваться ей могут только сотрудники;
- руководство хочет знать, какие напитки готовились.

Менять ради этого класс кофемашины не хочется: у него одна задача — варить кофе.
А клиентский код, который заказывает напитки, вообще не должен об этом знать.

**Заместитель** — это объект с тем же интерфейсом, что и настоящий. Клиент работает
с ним, как с настоящим, а заместитель сам решает, когда и как передать вызов дальше.

## Структура

```
   Клиент ──▶ CoffeeMachine (Субъект)
              ┌──────────────────┐
              │ + brew(drink)    │
              └────────▲─────────┘
           ┌───────────┴─────────────┐
   RealCoffeeMachine            Заместитель
   (Реальный субъект)   ┌──────────────────────────────┐
           ▲            │ _machine ◆───────────────────┼──▶ RealCoffeeMachine
           │            │ brew(drink):                 │
           │            │   проверка / журнал / кэш... │
           │            │   return _machine.brew(drink)│
           │            └──────────────────────────────┘
           └─────── создаётся или передаётся заместителю
```

## Виды заместителей в примере

| Класс                    | Вид                | Что делает                                         |
|--------------------------|--------------------|----------------------------------------------------|
| `LazyCoffeeMachine`      | виртуальный        | создаёт настоящую машину только при первом заказе  |
| `StaffOnlyCoffeeMachine` | защищающий         | пускает к машине только бариста и управляющего     |
| `LoggingCoffeeMachine`   | журналирующий      | записывает каждый заказ                            |
| `CachingMenuProxy`       | кэширующий         | **ваше задание**: запоминает цены из удалённого меню |

Бывает ещё **удалённый** заместитель: он выглядит как локальный объект, а на самом деле
отправляет вызовы по сети. Так устроены, например, клиенты RPC и ORM.

## Заместитель или Декоратор?

Устроены они почти одинаково: обёртка с тем же интерфейсом, которая хранит ссылку
на настоящий объект. Отличаются они **целью**:

|                          | Декоратор                              | Заместитель                                   |
|--------------------------|----------------------------------------|-----------------------------------------------|
| Зачем                    | **добавить** новое поведение            | **управлять доступом** к объекту               |
| Кто создаёт обёрнутый объект | клиент, и передаёт его в обёртку   | часто сам заместитель (как `LazyCoffeeMachine`) |
| Сколько обёрток          | обычно много, в любых сочетаниях        | обычно одна, известная заранее                |
| Результат вызова         | меняется (`cost()` растёт)              | тот же, что у настоящего объекта              |

## Когда применять

- Объект дорого создавать, и нужно отложить это до первого использования (виртуальный).
- Нужно проверять права перед вызовом (защищающий).
- Нужно кэшировать результаты медленных операций (кэширующий).
- Нужно журналировать обращения или считать их (журналирующий).
- Объект находится в другом процессе или на другом сервере (удалённый).

## ✏️ Задание

Меню с ценами хранится на сервере сети кофеен (`RemoteMenu`), и каждый запрос занимает 0,3 с.
Касса спрашивает цену при каждом заказе, и очередь растёт.

В файле [machine.py](machine.py) добавьте кэширующий заместитель `CachingMenuProxy(Menu)`:

- `get_price(drink)` — первый раз спрашивает настоящее меню, потом отдаёт сохранённую цену;
- `clear_cache()` — забывает сохранённые цены.

Место для кода помечено комментарием `# ЗАДАНИЕ`.

```bash
pytest tests/test_proxy.py
```

После этого запустите демо: время четырёх запросов сократится примерно вдвое.
